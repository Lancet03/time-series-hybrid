# Устройство time-series-hybrid

Это самостоятельный Python-пакет. Все реализации сетей включены в исходники;
соседние репозитории не импортируются и не читаются тестами.
Происхождение перенесённого кода и лицензия описаны в [THIRD_PARTY.md](THIRD_PARTY.md).

## Поток эксперимента

`cli.py` читает команду; `runner.py` разрешает YAML, загружает данные, выбирает
модели и validation-кандидатов, выполняет test и записывает артефакты.
`reporting.py` строит обычный HTML и объединяет совместимые результаты.

| Модуль | Назначение |
|---|---|
| `cli.py` | prepare-data, inspect, run, report, combine, lock-models, prefetch |
| `data.py` | Хэширование данных, хронологические splits, train-only scaling, ленивые окна |
| `evaluation.py` | Потоковые метрики, сохранение Parquet и составляющих гибрида |
| `runner.py` | Выбор моделей, обучение, validation-selection, запуск test, provenance |
| `reporting.py` | Таблицы метрик, sample std по seed, графики, объединение запусков |
| `models/registry.py` | Поддерживаемые типы и классы моделей |
| `models/base.py` | Model и Forecast, проверка форм и конечности значений |
| `models/ar.py`, `arima.py` | Локальная статистическая подгонка и причинные остатки |
| `models/dlinear.py` | Сеть DLinear и её адаптер |
| `models/tsmixer.py` | Сеть TSMixer и её адаптер |
| `models/moderntcn.py` | Сеть ModernTCN и её адаптер |
| `models/patchtst.py` | Сеть PatchTST и её адаптер |
| `models/itransformer.py` | Сеть iTransformer и её адаптер |
| `models/neural.py` | Общий trainer нейронных моделей |
| `models/layers.py` | Общие слои перенесённых сетей |
| `models/chronos.py`, `timesfm.py`, `moirai.py` | Отдельные адаптеры официальных FM API |
| `models/foundation.py` | Общая загрузка checkpoints и поканальный батчинг |
| `models/hybrid.py` | Базовый прогноз + FM-прогноз остатков |

## Сети и обучение

Пять нейронных архитектур используют включённые в проект определения классов.
В том же файле каждой сети расположен адаптер Model. Общий NeuralModel создаёт
ленивые train/validation loaders, Adam и MSE loss. Веса лучшей validation-эпохи
восстанавливаются после обучения. Test не участвует в выборе checkpoint.
Runner использует Base-варианты. Hyper-классы сохранены для совместимости исходников.

В общем протоколе loss и метрики взвешиваются количеством прогнозируемых значений.
Сохранённый профиль `hn_mvts_code` воспроизводит особенности прежнего обучения:
shuffle validation, усреднение validation/test по батчам и расход RNG на создание
неиспользуемого test-итератора. Это локальная настройка алгоритма, без загрузки
какого-либо внешнего кода или авторских логов.

## Статистические модели и гибриды

AR оценивает коэффициенты через NumPy-регрессию с ridge-штрафом без штрафа константы.
ARIMA вызывает statsmodels. Порядок выбирается на validation из кандидатов YAML.
При fit_prefix параметры оцениваются только по началу текущего контекста;
последующие точки обновляют состояние и дают причинные одношаговые ошибки.

Hybrid получает компоненты базы, подаёт доступную историю ошибок в замороженную
FM и складывает прогноз базы с поправкой. Квантили поправки сдвигаются на базовый
point forecast. В Parquet обе составляющие записываются отдельно.

Chronos, TimesFM и Moirai используют официальные библиотеки. Общий адаптер
раскладывает [windows, channels, context] в поканальные батчи и восстанавливает
формы выхода. Загрузка зависимостей и checkpoint происходит при создании FM,
поэтому статистические и нейронные модели не требуют установки всех FM extras.

## Конфиги и результаты

`benchmark.yaml` задаёт общий полный эксперимент и три гибрида. Сохранены также
полные профили нейронных сетей и фиксированного обучения DLinear. Проверочные
конфиги smoke/laptop/pilot удалены. Списки и пути моделей описаны в [README](README.md).

Прогнозы, метрики, validation-selection, ошибки, исходники и сведения об окружении
сохраняются в каждом outputs/run-id. Обычные отчёты и объединение результатов
не зависят от внешних эталонов. Код импорта/сравнения авторских логов и отдельный
модуль расширенного анализа гибридов удалены.

Старые reports/outputs сохраняются как история. Упоминания старых команд и конфигов
в них относятся к версии, на которой были получены соответствующие результаты.
Текущие команды находятся в [RUN_GUIDE](RUN_GUIDE.md).
