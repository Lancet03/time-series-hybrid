# ARIMA + Chronos: прогноз поправки по остаткам

Первый гибрид — существующий `Hybrid` с ARIMA как базой и замороженным
`amazon/chronos-bolt-tiny` как моделью остатков. Его отдельный полный эксперимент
описан в `configs/arima_chronos.yaml`. Реализация композиции —
`src/tshybrid/models/hybrid.py`; отдельные модели — `arima.py` и `chronos.py`.

## Схема

Для момента t и каждого канала отдельно:

```text
base[t+h] = ARIMA(доступная история), h = 1..H
e[tau] = y[tau] - прогноз ARIMA для tau, сделанный до наблюдения y[tau]
correction[t+h] = Chronos(доступная история e), h = 1..H
hybrid[t+h] = base[t+h] + correction[t+h]
```

Сначала ARIMA описывает динамику исходного ряда. Chronos получает историю её
одношаговых ошибок и прогнозирует возможную будущую поправку. FM не дообучается.
Проверяемая гипотеза: в остатках сохранилась прогнозируемая структура.
Если остатки близки к шуму, коррекция может ухудшить прогноз.

ARIMA оценивается на первых 128 точках контекста 336. Затем параметры фиксируются,
а состояние последовательно обновляется по следующим 208 наблюдениям через
causal filtering (`extend`). Только эти 208 одношаговых ошибок подаются Chronos.
Будущие test-targets не используются для построения входа FM. Простое вычитание
in-sample fitted values после обучения ARIMA на всём контексте здесь не применяется.

## Сравнение

В одном запуске оцениваются три модели:

| ID | Что прогнозирует |
|---|---|
| `arima` | Исходный ряд |
| `chronos` | Исходный ряд |
| `arima_chronos` | ARIMA + Chronos на ошибках ARIMA |

У всех одинаковые targets, splits, origins, горизонты и train-only scaling.
При этом standalone Chronos получает 336 исходных точек, а residual Chronos —
208 ошибок; эта разница является частью зафиксированного протокола.
Выбирается порядок ARIMA по validation MSE: кандидаты (2,1,0) и (2,0,0).
Гибрид использует ту же выбранную базу, что и standalone ARIMA, без выбора по test.

Для вывода о пользе гибрид должен улучшать test MSE/MAE относительно обоих
baseline, а не только одного. Проверка на нескольких окнах подтверждает работу
кода, но не качество на полном test и не научную новизну.

## Полный запуск ETTm1

```powershell
cd C:\workspace\learning\research\time-series-hybrid
.\.venv\Scripts\python.exe -u -m tshybrid run configs/arima_chronos.yaml
```

Контекст 336, все 7 каналов, горизонты 48/96, все validation/test окна, seed=0.
ARIMA использует 4 CPU-процесса, Chronos — CUDA при доступности.
Ревизия checkpoint берётся из `configs/model-lock.json`.
Для H=96 используется предусмотренный Chronos-Bolt rollout за пределы native H=64;
это отражено в metadata и одинаково для raw и residual FM.

Команда создаёт шесть задач и единый обычный `report.html`, `metrics.csv`,
`aggregate.csv`. В прогнозах гибрида сохранены отдельно `base_prediction`,
`correction`, их scaled-версии и итог. Прогресс отображается по окнам, эпох у
замороженной FM нет. Зависимости подключаются автоматически и при выборе
только `--models arima_chronos`.

Этот трёхмодельный запуск содержит новые результаты ARIMA и Chronos. При
объединении с предыдущей серией следует выбрать одну версию результата каждого
model/horizon/seed: combine отклоняет дубли. Старые результаты не перезаписываются.
