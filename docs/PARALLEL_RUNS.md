# Десять моделей в отдельных терминалах

Набор запускает AR, ARIMA, DLinear, TSMixer, ModernTCN, PatchTST, iTransformer,
Chronos, TimesFM и Moirai на одном ETTm1. Гибриды не включены.
Исходные эпохи, seed, горизонты, каналы и все окна из benchmark.yaml сохраняются.

## Подготовка и запуск

PowerShell из каталога проекта:

```powershell
$batch = "outputs/parallel-ETTm1-$(Get-Date -Format yyyyMMdd-HHmmss)"
.\.venv\Scripts\python.exe -m tshybrid.parallel prepare --dataset ETTm1 --output $batch
powershell -NoProfile -ExecutionPolicy Bypass -File "$batch/Start-All.ps1"
```

Подготовка не запускает модели. Она создаёт десять снимков YAML и PowerShell-скрипты.
`Start-All.ps1` открывает десять видимых терминалов с названиями моделей.
В каждом показывается обычный прогресс эпох/окон и ETA текущего этапа.
ExecutionPolicy Bypass используется только для нового процесса; системная
политика выполнения сценариев не меняется.

По умолчанию три модели работают на CPU: AR, ARIMA, Moirai. Пять нейронных сетей,
Chronos и TimesFM используют устройство исходного конфига: `auto` выбирает CUDA
при её доступности. В основном окружении сейчас установлена CUDA-сборка PyTorch;
у Moirai отдельное CPU-окружение. Для выбора другого устройства до запуска можно
отредактировать `device` в соответствующем снимке `configs/<model>.yaml`.

CPU-потоки ограничены: 1 для основной модели, 2 для Moirai. ARIMA сохраняет
четыре независимых процесса, внутри каждого один BLAS/OpenMP-поток. CPU-процессы
не инициализируют GPU: им задаётся пустой CUDA_VISIBLE_DEVICES.

Все семь GPU-задач делят одну видеокарту и её память. Одновременный запуск не
гарантирует ускорения: при CUDA out of memory неудавшуюся модель следует перезапустить
после освобождения памяти. Размеры сетей и batch size автоматически не уменьшаются.
Для сравнения времени моделей нужны отдельные последовательные запуски.

## Состояние и журналы

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$batch/Status.ps1"
```

В строке каждой модели: статус, номер текущей задачи, число пройденных эпох,
текущий этап. Внутри каталога набора:

- `plan.json` — модели, интерпретаторы, устройства и пути;
- `configs/*.yaml` — независимые снимки конфигов;
- `logs/<model>.log` — весь вывод, включая предыдущие попытки;
- `state/<model>.json` — статус, PID и точный каталог завершённого результата;
- `runs/<model>/<run-id>/` — прогнозы, веса, метрики и живой progress.json.

Повторный `Start-All.ps1` пропускает уже завершённые и работающие модели.
Блокировка предотвращает дублирующий одновременный запуск одной модели в одном наборе.
Можно открыть только отдельную модель, например:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$batch/patchtst.ps1"
```

Перезапуск одной модели начинает её полный эксперимент заново, без продолжения
с прерванной эпохи. Старые каталоги результатов сохраняются; журнал дописывается.
Состояние указывает результат последней попытки, остальные модели не затрагиваются.

Если в failures.json указан `WinError 5` при замене `progress.tmp` на `progress.json`,
это сбой записи снимка прогресса, а не ошибка вычислений модели или CUDA OOM.
Исправленный writer повторяет замену и при длительной блокировке откладывает
снимок, сохраняя обучение и прогресс в памяти. Консоль и CSV истории продолжают
работать; число отложенных записей сохраняется в `snapshot_write_errors`.
Исправление действует в новых процессах. Уже работающие модели автоматически
не обновляются и не останавливаются.

Для повторного запуска двух упавших моделей последовательно:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$batch/dlinear.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File "$batch/itransformer.ps1"
```

Это повтор полного набора выбранной модели: DLinear — 500 эпох суммарно,
iTransformer — 250. Успешные результаты других моделей остаются на месте.

## Объединение

Запустите сразу после открытия терминалов или после их завершения:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$batch/Combine.ps1" -Wait
Invoke-Item "$batch/combined/report.html"
```

`-Wait` ждёт всех десяти моделей. При failed/interrupted объединение останавливается
с указанием модели для перезапуска. Без `-Wait` незавершённый набор сразу отклоняется.
В объединение попадают точные каталоги из state-файлов, а не произвольные последние
запуски в outputs/. Стандартная проверка требует одинаковые данные, splits, каналы,
контекст, горизонты, origins и отсутствие дублей model/seed.

В `combined/` создаются `report.html`, `metrics.csv`, `aggregate.csv`.
Для полного ETTm1 ожидаются 60 строк метрик: 50 нейронных обучений и по два
результата AR, ARIMA, Chronos, TimesFM, Moirai. Каталог combined должен быть новым;
повторное объединение поверх существующего результата не перезаписывает его.

Каталоги outputs/ не входят в Git. На другом компьютере сначала выполните prepare
заново из его каталога проекта: в снимках записываются абсолютные локальные пути.
Конфиги и код следует зафиксировать до начала серии и не редактировать во время работы.
