# Протокол общего эксперимента

## Данные

Матрица `[time, channels]`: NPY или wide CSV с необязательным `date`.
NaN/Inf, нерегулярные и повторяющиеся CSV timestamps отклоняются; импутация и
ресемплинг должны быть явным решением. У NPY timestamps отсутствуют: частота и
семантика каналов наследуются от исходной подготовки и не проверяются независимо.

Origin t — первая неизвестная точка: контекст `[t-L,t)`, цель `[t,t+H)`.
Targets полностью внутри соответствующего split; история может пересекать предыдущий
split. В следующем origin ранее наблюдённые точки test становятся доступной историей.
Оба профиля включают последнее полное окно; они различаются обучением и агрегацией метрик.
Все модели одного H используют одинаковые origins.
`limit` равномерно выбирает индексы, включая края: это pilot.

Mean/std — отдельно по каналам, только train; для постоянного канала scale=1.
Нормализованные значения float32, суммы метрик float64. Окна читаются лениво.

## Модели и выбор

- AR/ARIMA локально подгоняются на каждом origin; порядок выбирается по validation MSE.
  `fit_prefix=128` означает оценку параметров по первым 128 точкам текущего контекста,
  затем коэффициенты фиксированы. AR использует наблюдённые лаги, ARIMA обновляет
  состояние causal filtering через `extend`. Отдельная база и гибрид работают одинаково.
- Без `fit_prefix` отдельный AR/ARIMA подгоняется по всему контексту. Такой baseline
  допустим как дополнительная абляция, но не идентичен prefix-базе гибрида.
- ETS — оптимизированный Holt-Winters, по умолчанию аддитивный тренд без сезонности;
  это не перебор всех ETS-спецификаций. Сезонность настраивается явно.
- DLinear, TSMixer, ModernTCN, PatchTST, iTransformer — собственные реализации
  архитектур Base-сетей HN-MVTS в `models/`, без импортов эталонного кода. RevIN,
  Adam/MSE; лучшая эпоха выбирается по validation. DLinear использует общие для
  каналов линейные слои сезонной/трендовой компоненты, kernel=25.
  `linear` использует один линейный слой; train_limit/stride явно записаны в конфиге.
- FM заморожены, работают поканально без ковариат. Point у Chronos-Bolt — медиана,
  у TimesFM — native point head, у Moirai — среднее 100 samples. Функционалы различаются:
  это учитывать при сравнении MSE и MAE.
- Native horizon Chronos-Bolt Tiny — 64. Для H>64 явно разрешён upstream rollout;
  это экстраполяция с ограничениями качества.

Для FM RNG сбрасывается после загрузки, чтобы cache не менял семплирование.
Перед test используется `seed+1000`. Разброс нейросетевых seed не заменяет оценку
устойчивости по разным рядам и датасетам.

## Гибрид

Первые W точек контекста — warmup. Для AR/ARIMA fit_prefix должен совпадать с W.
Остатки последующих точек — ошибки одношаговых прогнозов, сформированных до
наблюдения target. ARIMA использует innovations causal filter, не сглаживание.

FM получает L-W остатков, прогнозирует H поправок. Итог = база + поправка.
Обе части используют исходный контекст L: скрытого доступа к 2L точкам нет.
При L=336, W=128 FM получает 208 остатков, а standalone FM — 336 исходных значений.
Влияние этой разницы требует абляции. Одношаговые остатки не обязаны иметь структуру
многошаговой ошибки; преимущество схемы — проверяемая гипотеза.

Квантили остатка сдвигаются на point базы. Они описывают условную неопределённость FM,
не полную неопределённость параметров базы. Покрытие измеряется, а не гарантируется.

В Parquet гибрида сохраняются `base_prediction_scaled` и `correction_scaled`, а также
`base_prediction` и `correction` в исходных единицах. Для базы применяется scale+mean,
для коррекции только scale. Перед построением исследовательского отчёта проверяются
одинаковые origin/channel/lead и targets всех трёх вариантов, совпадение самостоятельной
ARIMA с компонентой гибрида и равенство hybrid=base+correction в обеих шкалах.

Для расширенного сравнения используются `hybrid_core.yaml` и `hybrid_moirai.yaml`.
Количество каналов ECL увеличено до 16, выбранных равномерно по индексам 0..320;
ETTm1 и Weather используются целиком. У Moirai отдельная копия той же ARIMA-конфигурации
в её окружении. Это исключает сравнение гибрида с базой, рассчитанной другой версией SciPy.
Используемый ARIMA — ограниченный локальный baseline с двумя кандидатами порядка и
prefix-fit; результаты не обобщаются на все настройки ARIMA/SARIMA.
Для двух конфигов расширенного сравнения задана approximate diffuse initialization
состояния: этот режим устраняет наблюдавшийся LU-сбой стационарной инициализации на
Weather. Это изменение алгоритма явно отражено в metadata; предыдущие результаты
с default initialization не смешиваются с новой таблицей. История первого неполного
прогона остаётся в outputs с `completed_with_failures`.

## Метрики и стоимость

- `mse`, `mae`: train-standardized units, сумма ошибок / число элементов.
- `mse_raw`, `mae_raw`: исходные единицы, которые могут различаться между каналами.
- `mase`: ошибки каждого канала / средняя абсолютная сезонная разность только train,
  затем равновесное усреднение. Нулевой масштаб даёт неопределённый MASE канала:
  он исключается; `n_mase_values` показывает фактическое число значений.
- Для квантилей: pinball_0.1/0.5/0.9, coverage_80, width_80, interval_score_80,
  crossing_80. Ширина/score в standardized units; в Parquet квантили в исходных единицах.
- `by_lead.csv` — отдельно lead=1..H; итоговая метрика охватывает весь H.
- `model_init_seconds`, `fit_seconds`, `validation_seconds` относятся к выбранному
  кандидату; `selection_seconds` включает всех кандидатов. `prediction_seconds` —
  вызовы прогноза test, без записи Parquet/метрик. Подгонка локальных AR/ARIMA входит
  в prediction time. Cache влияет на initialization time.
- `peak_rss_mb` — сэмплированный RSS всего процесса, включая ранее загруженные FM,
  не отдельная память весов и не GPU VRAM. Для строгого timing запускать модели отдельно,
  одинаково учитывать cold/warm cache и исключать параллельные эксперименты.
  Первые CPU-прогоны не являются строгим timing benchmark.

Ошибки перекрывающихся окон зависимы. Пилот на 8 origins не доказывает значимость.
Проверка пересечения ETT/Weather/ECL с pretraining checkpoints пока не завершена:
`frozen` не означает доказанный unseen-dataset zero-shot режим.
