# Ускорение полного эксперимента

Проверено 28 октября 2026 на Windows, Python 3.12, RTX 5070 12 ГБ и CPU с 16
логическими ядрами. Основное окружение обновлено с `torch 2.14.1+cpu` до
`torch 2.14.1+cu130`. Выполнены реальные GPU-вычисления, обучение всех пяти сетей
с сохранением весов, прогнозы Chronos/TimesFM и два гибрида через CLI.

## Что изменено

- ARIMA обрабатывает независимые окна/каналы в процессах joblib/loky. В полном
  benchmark по умолчанию `workers: 4`; пул переиспользуется между батчами.
  В каждом процессе ограничены внутренние BLAS/OpenMP-потоки, чтобы избежать
  конкуренции нескольких уровней параллелизма. Результаты возвращаются в порядке
  исходных окон и каналов. `workers: 1` сохраняет последовательный режим.
- Предупреждения ARIMA собираются в `metadata.warning_counts`, число подгонок —
  в `metadata.fit_calls`. Несходимость по-прежнему учитывается отдельно. Ошибки
  подгонки не подавляются: отказ validation-кандидата и сбой test обрабатываются
  runner так же, как прежде.
- Для нейронных сетей включены pinned memory и non-blocking CPU→GPU copies при
  использовании CUDA. Загрузчики остаются с нулём subprocess workers: окна уже
  находятся в RAM, лишние процессы для такой загрузки не добавлялись.
- Суммы train/validation loss накапливаются на устройстве. Убран вызов `.item()`
  на каждом батче, вызывавший принудительную синхронизацию CUDA.

## Измерения

| Проверка | До | После | Ускорение |
|---|---:|---:|---:|
| ARIMA(2,1,0), 448 подгонок ETTm1, L=336, prefix=128, H=48 | 6,282 с, 1 процесс | 1,420 с, 4 процесса | 4,42× |
| PatchTST, 20 обучающих батчей, batch=64, 7 каналов, L=336, H=48 | CPU 2,571 с | CUDA 0,082 с | 31,47× |

Оба замера выполнены после прогрева. PatchTST измеряет только вычисления модели
и Adam на готовых тензорах, без загрузки данных, validation и записи результатов.
ARIMA измеряет один порядок на выборке окон. Эти коэффициенты не являются
обещанием такого же ускорения всей исследовательской серии.
Сырые локальные замеры: `outputs/performance-check-20261028/timings.json`.

## Оценка полной серии на одном ETTm1

После добавления прогресса выполнена калибровка: для каждой сети и горизонта
замерена одна полная эпоха на всех train/validation окнах ETTm1. Прогнозирование
замерено на выборках из 256 origins для основного окружения и 64 для Moirai.
ARIMA замерена на 64 origins со всеми семью каналами для обоих порядков.
Длительность экстраполирована на полный validation/test и заданное число эпох/seed.
Полная исследовательская серия не запускалась.

Конфигурация: первые 57600 точек ETTm1, все 7 каналов, L=336, H=48/96,
пять seed у нейронных сетей, CUDA в основном окружении, 4 процесса ARIMA,
4 CPU-потока, Moirai CPU с 100 samples. Гибриды в эту оценку не включены.

| Модель/группа | Оценка, оба горизонта и все seed |
|---|---:|
| DLinear | 17 мин |
| TSMixer | 10 мин |
| ModernTCN | 27 мин |
| PatchTST | 7 мин |
| iTransformer | 12 мин |
| Chronos | 5 мин |
| TimesFM | 48 мин |
| ARIMA | 38 мин |
| AR | Менее минуты по прежнему полному замеру |
| Moirai, CPU | 145 мин |

Суммарный ориентир — около 5 часов 10 минут. Для планирования разумен диапазон
4–7 часов: одна эпоха не отражает весь длительный запуск, время ARIMA зависит
от конкретных окон, а конкурирующие процессы и запись артефактов меняют скорость.
Число эпох не является одинаковой единицей стоимости для разных архитектур.
Запланировано 50 обучений нейронных моделей, суммарно 1250 эпох.
Сырые калибровки: `outputs/eta-ettm1/core.json`, `outputs/eta-ettm1/moirai.json`.

В консоли теперь выводятся `[Task N/total]`, эпоха, время эпохи, лучшая эпоха и ETA
текущего обучения. Прогресс по train/validation батчам и validation/test origins
обновляется примерно раз в 10 секунд и в конце этапа. Общий живой снимок —
`progress.json`, CSV истории дописывается после каждой эпохи. ETA отдельного
этапа не является оценкой всей оставшейся серии.

## Сохранение протокола

Сохранены исходные контекст, горизонты, batch size, эпохи, seed, все окна,
кандидаты ARIMA и частота её подгонки. AMP, TF32, сокращение сетей и ранняя
остановка не включались. Смена CPU на GPU может изменить численные результаты.

Параллельные прогнозы и причинные остатки ARIMA сверены с последовательными
с допуском `1e-10`. Проверено сохранение счётчиков предупреждений и несходимости.
Обучение всех пяти сетей сравнено с предыдущим кодом отдельно на CPU и CUDA:
в проверке с фиксированным seed совпали веса и выбранная validation-эпоха.

## Moirai

Uni2TS 2.0.0 требует `torch>=2.1,<2.5`; проверенное `.venv-moirai` использует
PyTorch 2.4.1 CPU. Несовместимая замена пакета в этом окружении не выполнялась.
Moirai остаётся на CPU; параллельная ARIMA работает и проверена в его окружении.
Для GPU-Moirai потребуется отдельная миграция совместимых зависимостей.

## Запуск

Используйте прежние команды `python -m tshybrid run configs/benchmark.yaml ...`.
`device: auto` теперь выбирает RTX 5070 в основном окружении. Новые настройки
действуют только при новом запуске процесса. Полная серия в рамках этой проверки
не запускалась; проверочные конфиги находятся только в игнорируемом `outputs/`.
